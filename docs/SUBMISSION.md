# 이별 장례식 — BYPP 제출서

## 왜 만들었나요?

썸 타던 사람이 잠수를 탔습니다. 저는 카톡을 붙잡고 답장 시간을 재고, "나중에 연락할게"가 진짜 나중인지 세 번쯤 다시 읽고, 캡처를 친구한테 보내 "이거 어때?"를 묻고 있었습니다. 친구도 ChatGPT도 감으로 답했습니다. 대화 전체를 붙여넣으면 앞부분은 잘리고 가운데는 잊혔습니다.

그때 든 생각이 두 가지였습니다. 하나는 "이건 감이 아니라 데이터로 볼 수 있는 문제다" — 카톡 내보내기 txt에는 누가 몇 분 만에 답했고, 누가 먼저 말을 걸었고, 대화가 언제 반토막 났는지가 전부 들어 있습니다. 다른 하나는 "분석만 해주면 더 집착하게 된다"는 것. 그래서 분석의 끝을 **장례식**으로 만들었습니다. 진단서를 받고, 관을 덮고, 꽃을 던지고, 부적을 태우고, 공동묘지에 안치하면 끝. 다시 열어볼 이유를 없애는 게 목적입니다.

제 상대는 회피형이라 데이터만 보면 "썸 진행 중"으로 나왔습니다. 그래서 "어떻게 끝났는지"를 사용자가 직접 알려주면 데이터 판정을 덮어쓰는 기능이 첫 실사용에서 바로 나왔습니다. 이 프로젝트의 첫 사용자는 저고, 첫 영정은 제가 그렸습니다.

## 주요 기능

1. **부검 (사망 진단서)** — 카톡 txt를 올리면 관계의 사망 진단서를 발급합니다. 마지막 말·사망 일시·사망 사유·**사망 원인 %**(전성기 4주 vs 말기 4주 비교: 상대 응답 둔화 / 대화량 급감 / 과다 선톡 / 잠수 등, 각 항목에 숫자 근거)·애정도 낙하 곡선·굵직한 업다운 사건(눌러서 그 주 원문 확인)·이별 신호(둘 사이 상대 비교). **숫자는 전부 코드가 계산하고 LLM은 조회·해석만** 합니다. 모든 사실에 원문 영수증이 붙습니다.
2. **이별 컨텍스트 덮어쓰기** — 잠수·차였음·내가 끝냄·자연소멸·합의 중 선택 + 상황 설명 + 관계 시작일/헤어진 날. 데이터 판정과 다르면 사용자 진술을 우선하고, 모든 LLM 프롬프트에 주입됩니다. 향년은 썸 시작일부터 셉니다(카톡은 사귀기 전부터 했을 수 있으니까).
3. **영정 그리기** — 상대 얼굴을 그림판으로 그리거나 사진을 올립니다. 진단서 액자와 관 속에 들어갑니다. 마스코트(테루테루보즈)는 '나'입니다.
4. **매장 의식** — 관 뚜껑을 드래그해서 덮고, 꽃을 골라 던집니다.
5. **진정성 진단서** — Claude가 실데이터 사실(답장 중앙값, 온도 변화, 침묵 일수)만 근거로 쓰는 팩폭 위로 편지.
6. **🔮 애착유형별 저주 부적** — 상대 애착유형에 따라 사자성어가 세로로 박힌 부적(회피형 `戀愛即逃`, 불안형 `前任常思`, 안정형 `前緣已斷 後悔未斷`, 혼란형 `來去無常`) + 상대 카톡 패턴으로 만든 맞춤 저주 한 줄. 전체화면 태우기 연출(불길·흔들림·한자 슬램·封 도장·합성 사운드).
7. **공동묘지** — Supabase 기반 공용 묘지. 로그인 없이 익명으로 헌화(묘비당 1회)·방명록. 저주봉인 묘비에는 미니 부적이 꽂혀 있습니다.
8. **현실 치료실** — **X 소환술**(상대의 실제 메시지 40개 + "내가 말했을 때 → 상대의 실제 반응" 페어로 말투를 복제한 시뮬레이터, 미련 던지면 팩폭), **레전드 썰 매칭**(내 데이터+이별 진술로 검색어를 만들어 네이트판·디시·더쿠·블라인드에서 실제 글을 웹 검색, 원문 링크·겹치는 점·현타 포인트), **선톡 방지 비상벨**.

## 사용한 AI 도구와 활용 과정

**Claude Code (Opus 5)로 기획부터 배포까지 1인 개발.** 활용 방식은 세 층이었습니다.

- **기획 검증**: "카톡 분석 개인 소통 코치"라는 넓은 아이디어를 들고 시작했는데, Claude Code로 3관점 심사위원(구현/매력/정체성) + 반박자 + 종합자 워크플로우를 돌려 채점시켰더니 최하위(10.4/30)가 나왔습니다. 이유는 "누구의 어떤 문제인지 한 문장으로 못 말함, 동기가 가설". 그 결과를 보고 제 실제 경험(썸 → 잠수)으로 좁혔고, 최종 컨셉 '이별 장례식'은 제가 HTML 프로토타입으로 그려서 던진 뒤 React로 포팅하게 했습니다.
- **구현**: 파서(카톡 PC/Android/iOS 3종), 온도 지수·업다운·단계 감지·대칭성·사망 원인 같은 통계 엔진, FastAPI, React 프론트, Supabase 스키마(RLS·RPC), Render/Vercel 배포 설정을 전부 Claude Code가 작성했고 저는 실데이터를 넣어보며 틀린 곳을 잡아냈습니다. 예: "사망 원인 전부 0%" → 최근 14일 창만 보던 로직을 전성기 vs 말기 비교로 재설계, "향년 496일" → 카톡 시작이 아니라 썸 시작일 기준으로.
- **LLM 기능 설계**: "LLM은 세지 않는다, 코드가 센다" 원칙. 코치는 원문을 통째로 받지 않고 툴(답장 통계·기간 요약·원문 검색·앞뒤 맥락)로만 조회하며, 매 턴 관계 요약 카드를 시스템 프롬프트에 주입해 긴 대화에서도 숫자가 밀리지 않게 했습니다. X 소환술은 상대의 실제 메시지와 반응 페어를 few-shot으로 넣고 "샘플보다 다정하거나 설명적이면 실패"라는 규칙으로 AI 티를 뺐습니다. 레전드 썰은 Claude 웹 검색 툴로 실제 커뮤니티 글을 찾습니다.
- **디자인 정리**: 마지막에 "AI가 만든 UI 냄새"를 항목별로 진단하는 프롬프트(이모지 83개, 손글씨체 20곳, 기본 easing, hover -1px 8곳, 개발자 문장 노출 등)를 만들어 돌리고, 모션 토큰·아이콘 14종 직접 그리기·비대칭 SVG·반말 통일로 한 번에 정리했습니다.

개발 중 자체 테스트(제 카톡 + 지인 1명)에서 나온 것들은 이렇게 반영했습니다:
- "회피형이라 데이터가 썸이라고 함" → 이별 컨텍스트 입력 + 데이터 판정 덮어쓰기
- "향년이 카톡 시작부터 세짐" → 썸 시작일 기준 + 데이터 추천값 + 진단서에서 수정
- "사망 원인이 전부 0%" → 전성기/말기 비교로 재설계, 침묵 기간은 오늘 기준
- "그래프가 주식 차트 같다 / 짧은 관계가 오른쪽에 압축됨" → 관계 시작일부터만, 펜 자국 두 겹 선
- "친구 방 올리라는 요구는 필요 없다" → 없으면 둘 사이 상대 비교로 자동 전환
- "캐릭터는 X가 아니라 나다" → 영정은 직접 그리거나 사진, 마스코트는 나로만
- "레전드 썰이 진짜 돌아가는 거 맞나" → 실제 사용한 검색어와 근거(상대 성향·이별 방식)를 화면에 표시
- "공동묘지에 로그인 없이 남이 헌화·댓글 되게" → Supabase + 익명 ID, RLS로 수정·삭제 차단
