## 0. 한 장 요약

| 항목 | 내용 |
|---|---|
| 문제 | 썸/연애 중에 카톡을 붙잡고 답장 시간을 재고, 문장을 고치고, 캡처 한 장 들고 친구나 ChatGPT에 "이거 어때?"를 묻는다. 답은 늘 감(感)이고, 대화 전체를 붙여넣으면 잘리거나 잊는다. |
| 해결 | 카톡 대화 전체를 구조화해 저장하고, **숫자는 코드가 세고 LLM은 조회만** 한다. 관계의 온도·대칭성·추세를 계기판으로 보여주고, 모든 답변에 원문 근거(영수증)를 붙인다. |
| 동기 | 개발자 본인이 썸탈 때 겪은 경험. 발표 첫 문장. |
| 타겟 | 신경 쓰이는 사람이 있는 모든 카톡 사용자 — 썸인지 모르는 사람(모솔 포함)·썸·연애·이별 (1차: 대학생) |
| 차별점 | ① 내 다른 대화 전체가 baseline → "나의 편향" 계산 가능 ② 시간축(온도 추세) ③ 모든 주장에 근거 링크 ④ 상대 마음을 판정하지 않고 내 행동과 관계 모양을 보여줌 |
| 안 하는 것 | 실존 인물 얼굴 생성, "좋아할 확률", 상대 동의 없는 상대 심리 판정 문구, 실시간 수집(v0) |

## 1. 제품 원칙

1. **LLM은 세지 않는다.** 시간·비율·횟수는 전부 코드가 계산. LLM은 툴로 조회하고 해석만 한다.
2. **영수증 원칙.** 코치의 모든 사실 진술은 메시지 ID 근거를 가진다. 근거 없는 숫자는 출력 금지.
3. **나 중심.** 분석 대상은 "나의 행동"과 "관계의 대칭성". 상대의 감정을 단정하는 문장("걔는 너 안 좋아해")은 금지. 데이터 서술("상대 답장 속도가 3주간 2.1배 느려짐")만 허용.
4. **투명한 지수.** 온도 지수는 공식과 구성요소를 항상 함께 보여준다.
5. **정직한 데이터 흐름.** 통계·온도·미답장 판정은 로컬 코드. LLM(API)에는 가명 치환된 요약 대상 구간 원문·툴 결과·초안용 최근 메시지만 전송하며, 무엇이 나가는지 화면에 표시한다. "전부 로컬"이라고 말하지 않는다.
6. **엔진 하나, 렌즈 셋.** 썸/연애중/이별은 같은 데이터·같은 지표에 질문과 톤만 다르다.

## 2. 사용자 플로우

```
[랜딩] "카톡 대화 넣으면, 이 관계의 온도를 재줄게"
   │  txt 드롭 (여러 개 가능) / 샘플로 보기 / (Windows) 카톡 연결
   ▼
[누가 나야?] 참여자 목록에서 나 선택 · 가명 처리 토글(기본 ON)
   ▼
[누구 얘기야?] 상대 선택 (1:1 방 자동 추천). 나머지 방은 baseline으로만 사용
   ▼
[분석 중] 진행 로그 스트리밍 (파싱 → 통계 → 에피소드 요약 → 인물 카드)
   ▼
[관계 뷰]  좌: 온도 게이지 + 타임라인 + 대칭성 · 우: 코치 채팅 (봇이 먼저 말 검)
   ├─ 탭: 인물 카드 / 리허설 / 주간 리포트
   └─ 단계 렌즈: 썸 · 연애중 · 이별 (자동 감지, 수정 가능)
```

## 3. 기능 명세

우선순위: **P0** 해커톤 데모 필수 · **P1** 있으면 강함 · **P2** 이후

### F1. 데이터 수집

| ID | 기능 | 우선 | 설명 |
|---|---|---|---|
| F1.1 | txt 업로드 | P0 | 카톡 내보내기 txt 다중 업로드. PC/Android/iOS 포맷 자동 감지. 인코딩 utf-8/cp949 자동. |
| F1.2 | 샘플 데이터 | P0 | 가상의 썸→연애→식음 시나리오 6개월치 + 친구방 2개. 심사위원 체험용. |
| F1.3 | 카톡 PC 자동 내보내기 (이름 입력) | P0-데모 | Windows 전용. "상대방 카톡 이름" + "비교할 친구 이름 2명" 입력 → 카톡 PC 검색으로 방 열기 → ≡ → 대화 내용 → 내보내기 → 저장 대화상자 처리 → 즉시 파싱. 실제 입력이 필요해 약 10초 손 떼기 안내. 실패·비Windows는 F1.1 폴백. |
| F1.4 | 증분 추가 | P1 | 같은 방 txt를 다시 올리면 중복 제거 후 새 메시지만 추가, 새 구간만 재요약. |
| F1.5 | 인스타 DM JSON | P2 | 메타 데이터 다운로드 파서. |

**규칙**: 헤더의 "저장한 날짜"를 파싱해 `saved_at`으로 저장 — 미답장 판정의 "현재 시각"은 데이터 마지막 메시지가 아니라 이 값(없으면 파일 수정시각). 시스템 메시지(입장/퇴장/삭제) 제거. "사진/이모티콘/동영상" 단독 메시지는 `media` 플래그로 보존(분량 계산에서 제외, 빈도 계산에는 포함).

### F3. 관계 온도 지수 (핵심)

**정의**: 0~100. 코드가 계산. 구성요소 7개, 가중치 공개·조정 가능. 메시지 30개 미만 창은 `sparse` 표시.

| 구성요소 | 기호 | 계산 (0~1 정규화) | 가중치 |
|---|---|---|---|
| 상대 응답성 | R | 상대 답장 중앙값(분). 5분 이하=1.0, 24시간 이상=0.0, 로그 스케일 보간 | 0.20 |
| 대화 빈도 | F | 이번 창의 메시지/일 ÷ 관계 평시 빈도(활발했던 주들의 중앙값). 같으면 1.0, 1/10이면 0.0 (로그) | 0.15 |
| 시작 균형 | I | `1 - |내 대화시작 비율 - 0.5| × 2` (대화 세션 = 6시간 이상 공백 후 첫 메시지). 세션 6개·메시지 30개 미만이면 제외 | 0.10 |
| 분량 균형 | V | `1 - min(1, |log2(내 글자수 / 상대 글자수)| / 2)`. 양쪽 150자·메시지 30개 미만이면 제외 | 0.10 |
| 관심 신호 | Q | 상대 메시지 중 질문(?) 비율·ㅋㅋ/이모지 밀도를 baseline(상대의 다른 방은 없으므로 **내 다른 방의 상대들 평균**) 대비 정규화 | 0.15 |
| 추세 | T | 최근 14일 vs 이전 28일: 메시지/일 변화율과 상대 응답 중앙값 변화율의 평균 → -1..1 → 0..1 | 0.20 |
| 감정 어휘 | E | 주간 에피소드 카드의 mood(-2..+2) 최근 4주 평균 → 0..1 (F6 필요) | 0.10 |

`온도 = 100 × Σ(wᵢ × cᵢ)`. E 미계산 시 나머지 가중치 재정규화.

**출력**: 현재 온도, 지난주 대비 Δ, 구성요소별 값과 기여도, **하락/상승 주요인 1개** (기여도 변화 최대 항목) + 근거 메시지 ID.

**금지**: "좋아할 확률", "그린라이트" 표현. 온도는 관계의 *모양*이지 상대의 *마음*이 아님을 UI 문구로 고정.

### F3b. 썸 신호 판정 (모솔 진입점)

**목적**: 연애 중이 아니어도 "나와 이 사람, 썸이야?"에 답한다. 상대 마음이 아니라 **관계 모양에서 보이는 신호**를 양쪽으로 나눠 점수화.

| 항목 | 계산 |
|---|---|
| 내 쪽 신호 (0~100) | 나의 편향(F5.2): 답장 속도 배수, 문장 길이 배수, 질문 비율 배수, ㅋㅋ/이모지 배수, 새벽 대화 비율 — 각 항목 baseline 대비 로그 스케일 |
| 상대 쪽 신호 (0~100) | 상대 응답 중앙값(R), 상대 질문 비율·이모지 밀도(내 다른 방 상대들 평균 대비), 상대가 먼저 말 건 비율, 상대 글자 비중, 상대 새벽 대화 |
| 판정 | 둘 다 ≥55 **서로 신호 있음** · 나만 ≥55 **내 쪽만 뜨거움** · 상대만 ≥55 **상대가 더 적극적** · 그 외 **아직 친구 모양** |
| 근거 | 각 쪽 상위 3개 사실 + msg_id. "좋아한다/안 한다" 문구 금지. |

UI: 홈 최상단 마스코트 말풍선이 판정을 말함. 모솔 사용자는 이 카드가 첫 화면의 전부여도 됨.

### F4. 관계 타임라인 + 단계 자동 감지

| ID | 기능 | 우선 | 설명 |
|---|---|---|---|
| F4.1 | 주간 지표 시계열 | P0 | 주별: 메시지/일, 상대·내 응답 중앙값, 내 시작 비율, 새벽(01~05시) 비율, 온도 |
| F4.2 | 단계 자동 감지 | P0 | 규칙 기반 세그먼트: **썸**(빈도 상승 + 응답 빠름 + 시작 균형) · **연애**(고빈도 안정 + 아침/밤 인사 어휘 주 4회 이상) · **식음**(빈도 하락 + 응답 둔화 + 시작 편중 ≥ 0.7) · **단절**(7일 이상 무대화 후 저빈도). 세그먼트별 confidence. |
| F4.3 | 사용자 수정 | P0 | "여기부터 사귐" 등 경계 수정 → 저장 → 렌즈·프롬프트에 반영. 수정 로그는 피드백(F12)으로 기록. |
| F4.4 | **업다운 사건** | P0 | 주간 온도 시계열에서 국소 고점/저점(|Δ| ≥ 10°) 자동 검출 → 각 사건에 기여도 1위 구성요소 + 에피소드 카드 제목·근거 msg_id 부착. 타임라인 위에 ▲▼ 마커, 클릭 → 원문. "굵직한 업다운"이 이 화면의 주인공. |
| F4.5 | 사건 카드 목록 | P0 | 업다운 사건을 시간순 카드로: "3/14 ▲ +14° 첫 '보고 싶다'" / "7/25 ▼ -18° 다툼, 상대 응답 4배 둔화". |

### F6. 에피소드 기억 (컨텍스트 문제 해결)

**목적**: 대화가 아무리 길어도 코치가 "3월 14일에 처음 '보고 싶다'가 나왔다"를 근거와 함께 말할 수 있게.

| 층 | 내용 | 우선 |
|---|---|---|
| L0 원문 | SQLite, 메시지 ID. 코드가 직접 계산. | P0 (완료) |
| L1 세션 | 6시간 이상 공백 기준으로 대화 세션 분할. 세션별 시작자·종료자·길이·시간대 저장 (F3, F5 입력). | P0 |
| L2 에피소드 카드 | 주 단위(또는 세션 40개 단위)로 Claude가 요약. 스키마: `title, summary(3문장), mood(-2..2), key_events[], notable_quotes[{msg_id, why}], topics[], my_behavior_note, their_behavior_note`. 근거 msg_id 필수. | P0 |
| L3 월 카드 | 에피소드 카드 4~5개 → 월 요약 + 관계 상태 한 줄. | P1 |
| 검색 | 날짜 범위 · 키워드 · mood 범위 · 사람으로 카드/원문 조회 툴. 임베딩 검색은 P2. | P0 |
| 증분 | 새 메시지가 붙은 주만 재요약. | P1 |

**영수증 UI**: 코치 답변 내 `[#msg_id]` 토큰을 프론트가 칩으로 렌더 → 클릭 시 원문 패널로 점프·하이라이트.

**비용/성능 가드**: 요약은 병렬(주 단위 독립) 실행, 최대 동시 8. 6개월치(약 5만 메시지) 기준 목표 20초 이내. 캐시(파일 해시 기준).

| F9.5 | 복사 | P0 | 초안 클립보드 복사. 카톡 자동 전송은 **하지 않음**. |

**말투 재현 규격 (F9.1 / F9.0 공통, "AI 티" 제거)**

1. *스타일 프로필(코드 추출)*: 문장 길이 분포(중앙값·p90), 마침표/물음표/느낌표 사용률, 띄어쓰기 습관(붙여쓰기 비율), ㅋ/ㅎ/ㅠ 길이 분포("ㅋㅋ" vs "ㅋㅋㅋㅋ"), 초성·축약어 사용("ㅇㅇ","ㄱㄱ","넹","웅"), 자주 쓰는 어미 top 10("~함","~임","~요","~ㅋㅋ"), 문두 감탄사("아","헐","와"), 이모지·이모티콘 사용률, 한 번에 여러 메시지로 쪼개 보내는 비율, 존댓말/반말.
2. *상황별 실제 예시(검색)*: 지금 상황(상대 마지막 메시지 유형: 질문/제안/감정표현/일상보고)과 비슷한 과거 상황에서 **내가 실제로 보낸 답장** 8~15개를 few-shot으로 주입. 이 상대에게 보낸 것 우선, 부족하면 전체.
3. *금지 목록(프롬프트 고정)*: 완벽한 맞춤법·띄어쓰기(프로필이 그렇지 않으면), 문장 끝 느낌표 남발, "~하는 건 어때?", "혹시", "~인 것 같아요!", 과한 공감 문구("정말 힘들었겠다"), 설명조, 3문장 이상 한 덩어리(프로필 p90 초과 금지), 이모지 추가(프로필 사용률 < 10%면 0개), 존댓말/반말 전환.
4. *출력 후 검증(코드)*: 초안의 길이·ㅋㅋ 사용·마침표 사용·존댓말 여부를 프로필과 대조 → 허용 범위 벗어나면 그 항목을 명시해 1회 재생성. 프로필상 메시지를 쪼개 보내는 사람이면 초안도 2~3개 버블로 분할 출력.
5. *평가*: 내부 테스트 — 실제 내 메시지 10개와 초안 10개를 섞어 본인이 구분해보는 블라인드 테스트(정답률 60% 이하 목표). 결과를 F12 피드백에 기록.

## 7. 화면 구성

1. **랜딩** — 한 줄 카피, 드롭존, "샘플로 보기", (Windows) "카톡 연결", 내보내기 방법 접이식
2. **온보딩** — 나 선택 → 상대 선택 → 가명 토글 → 분석 로그
3. **관계 뷰** (메인, 2열)
   - 좌 상단: 온도 게이지(숫자·Δ·주요인) + 구성요소 펼침
   - 좌 중단: 타임라인(주간 온도·빈도 + 단계 세그먼트 배경색 + 사건 마커)
   - 좌 하단: 대칭 바 5개 · 나의 편향 4칩 · [사람 비교] 버튼
   - 우: 코치 채팅 (첫 인사이트, 추천 칩, 영수증 칩, 👍👎)
   - 상단 렌즈 스위치: 썸 · 연애중 · 이별 (자동 감지 배지)
4. **인물 카드** 탭 — 아바타 + 별명 + 능력치 + 특성(근거) + 말투 규칙 · [내 카드] 토글 · PNG 저장
5. **리허설** 탭 — 상대 마지막 메시지 → 초안 3안 → 선택 → 시뮬 반응(근거) → 수정 → 복사
6. **주간 리포트** 탭 — 카드 5장
7. **원문 패널** (우측 슬라이드) — 영수증 클릭 시 해당 메시지 ±10개

## 9. 비기능 요구

- **프라이버시**: 원문은 로컬 DB. LLM에는 가명 치환 후 (a) 에피소드 요약 대상 구간 원문 (b) 툴 결과 (c) 초안/리허설용 최근 메시지 ≤ 15건만 전송. 설정 화면에 데이터 흐름도 + "이번 요청에 전송된 내용 보기". 세션 데이터 삭제 버튼. (P1 서버 배포 시) 업로드 24시간 후 자동 삭제.
- **API 키 (릴리즈)**: 테스터는 키를 못 넣는다 → 개발자 키를 담은 릴레이 엔드포인트(일일 호출 상한, 토큰) 경유. 로컬 실행 시 `.env` 키가 있으면 직접 호출.
- **성능**: 5만 메시지 기준 통계 < 2초, 에피소드 요약 < 20초(병렬 8), 채팅 첫 토큰 < 3초.
- **안정성**: 요약 실패 주차는 건너뛰고 표시, 전체 실패로 번지지 않음. LLM 장애 시 통계 뷰는 정상 동작.
- **실행**: `run.bat` 한 번(백엔드+프론트). (P1) 백엔드 Fly.io/Render + 프론트 Vercel로 친구 테스터 링크.
- **비용 가드**: 요약 캐시, 리허설 세션 20턴 제한.

## 11. 열린 질문

1. **해커톤 마감일 / 발표일** — 구현 순서의 P0/P1 경계 확정에 필요.
2. **서비스명** — 후보: 온도(Ondo), 썸미터, 리시트(Receipt), 카톡 온도계. 발표 전까지 결정.
3. **실제 데이터로 데모할지** — 실제면 가명 처리 필수 + 상대방 메시지 원문 노출 최소화. 샘플 데이터로 하는 게 안전하지만 "내 경험" 서사와 약해짐. 절충: 실제 데이터로 통계·온도만, 원문 영수증 장면은 샘플로.
4. **테스터 배포 여부(F12.4)** — 하면 관점3 점수 크게 오르지만 서버 배포·삭제 정책·키 릴레이 작업 필요.
5. **실데이터 최우선** — 심사위원 예상 질문 1순위가 "본인 데이터로 돌려봤나, 숫자 하나 말해봐". 구현 1단계 직후 실제 export로 돌려 나온 숫자가 발표 서사를 결정하게 한다.
